# User-driven PR testing

The user performs all test actions, including UI setup, API requests, worker/job or CLI invocations, and shipped migrations, seeders, operations, and scripts, even when they are prerequisites. The agent provisions missing data through non-UI tooling: baseline seeds/factories and targeted application or database commands. For writes covered by [local test authorization](SKILL.md), the agent executes without asking again. Ask only when the safety boundary or tool requires it. Leave UI and shipped-artifact execution to the user; do not run them as hidden setup.

For each scenario, record exact navigation, field values, clicks or command, expected observation, and any persisted effect to verify. Show a short overview first; give details when the user reaches the scenario. Artifact instructions include the pre-check, command, and post-check. Inspect each artifact's target and pre-state and leave it pending for the user.

Guide one journey at a time — a short journey's numbered actions and expected observations can go in a single checkpoint rather than one scenario per turn; split longer journeys at meaningful boundaries. State what setup is ready, give the actions and expected observations, and wait for the user's report. Use the interactive question tool at meaningful checkpoints, not after every click. Guide one retry for an apparent missed step; otherwise record the application failure without investigating beyond scope.

Never infer success from silence or take over an unperformed user action. A declined or unavailable required test action makes its scenario `BLOCKED`. For declined or unavailable setup actions, follow [Step 6](SKILL.md#6-prepare-minimal-local-data) before marking the scenario `BLOCKED`. When the user ends the session, apply the shared deferral gate in [SKILL.md](SKILL.md). For artifacts, wait for the user's command output and verify the post-state. Supporting automated checks may run only if they do not execute shipped artifacts; give artifact-executing commands to the user.

Record the user's observation as UI evidence in the common [reporting contract](reporting.md), with supplied screenshots in its evidence directories. Request a screenshot or exact error only when needed to resolve ambiguity or support a finding. Distinguish user observations from agent-executed checks in the report; an observation without a screenshot is not itself a proof gap.
